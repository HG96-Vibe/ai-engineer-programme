The Programme

Ten Stages. One Application. A Portfolio You Can Defend.

Each stage below says what you learn, why it is in the programme, and what you build. The order is deliberate: nothing appears before you have the context to understand why it matters.

  • Theory first, told as a story — no tool appears before you know why it exists
  • The whole job built with no code, before a line of Python
  • One application extended stage by stage, not ten throwaway exercises
  • A capstone that ends live at a public URL, with an evaluation report

Stage by Stage

What You Learn, and What You Build

Stages 3 to 8 extend the same application rather than starting over, so you finish with one real system you can explain end to end in an interview.

01Phase 1Foundations: understand the whole jobStages 0–2
0

Foundations · no codeWhat AI actually is, and what an AI engineer actually does

Theory, told as a story

Everything a complete beginner needs before any tool appears. Told in six lectures as the story of how we got here, not as a textbook.

  • AI, machine learning, deep learning and large language models, and how they relate
  • Training a model versus using one, and why this programme is about the second
  • Tokens, context windows, embeddings, temperature, and why models make things up
  • The model landscape (Claude, GPT, Gemini, open-weight) and how engineers choose
  • Where AI sits inside ordinary software: the user, the app, the database, the model
  • The job itself: what UK adverts say the role is, and what it is not
You build

A written explainer, in your own words, of how an LLM answers a question. You will use it again in interview preparation.

1

The no-code full workflowCopilot Studio: the whole job before any code

The stage that makes everything else make sense

Copilot Studio lets you do the whole job before code makes it harder. You build a complete assistant and, as you do, you are told plainly which later stage each button corresponds to.

  • Build an assistant, write its instructions, give it a persona and constraints
  • Add knowledge sources: documents, SharePoint, a website. This is retrieval, and you are told so
  • Add actions that call a workflow or an API. This is tool use, and you are told so
  • Test it, break it, watch it hallucinate, fix it. This is evaluation, and you are told so
  • Publish it to Teams. This is deployment

This stack appears in a fifth of UK adverts and dominates junior and regional roles. Some students get their first job on it alone.

You build

An internal HR or IT policy assistant, published to Teams, answering from real documents and logging a ticket through an action.

2

Code foundationsPython for AI engineering

Application Python, not analysis Python

The Python of someone who writes services: functions, classes, data structures, JSON, error handling, reading a traceback, calling an HTTP API, virtual environments, project structure, Git, and a first test. Written by you, without an AI assistant finishing your lines; assistants are introduced deliberately in Stage 3.

  • Git and GitHub from day one; every later build lives in a repository
  • Enough to read TypeScript, since a third of adverts want it as a second language
You build

A command-line tool that pulls from a public API, handles errors, has tests, and is on GitHub with a README.

02Phase 2Building: one application, extended stage by stageStages 3–8
3

First contact with the modelWorking with LLM APIs

The Stage 1 assistant, rebuilt in code

Call a model from Python. System prompts, messages, structured outputs, streaming, cost and latency, and switching between two providers behind one interface. Then wrap it in a FastAPI service so it is an application, not a notebook.

  • Provider SDKs directly, no framework yet
  • AI-assisted development introduced here as a working practice, with one rule: you must be able to explain every line
You build

A chat service with conversation memory, exposed as an API, that can run against either of two model providers.

4

The craftContext engineering

Prompt engineering, folded into something bigger

Prompting matters, but no employer hires for prompting alone. This stage teaches it as one part of deciding what the model sees: prompts, examples, output schemas, tool descriptions, conversation history, what gets cut when the context is full, token budgeting, and defending against prompt injection.

You build

Your Stage 3 service upgraded to produce validated structured outputs and to resist a set of injection attacks you write yourself.

5

Build pattern oneRetrieval-augmented generation (RAG)

One of the two patterns every portfolio needs

The knowledge-sources button from Stage 1, opened up. Chunking strategies, embeddings, a vector store, keyword versus semantic versus hybrid search, reranking, citing sources, and measuring whether retrieval actually found the right thing.

RAG appears in roughly half of UK AI engineer adverts.

You build

Document Q&A over a private document set, such as a policy library or a product manual, with cited answers and a retrieval-quality score.

6

Build pattern twoAgents and tool use

The other pattern every portfolio needs

The actions button from Stage 1, opened up. Function calling, an agent loop written from scratch so you see there is no magic, then the same loop in a framework so you can read the ones employers name. Connecting to an MCP server. Failure handling, safe fallbacks, guardrails, and knowing when a plain workflow beats an agent.

  • Raw SDK first, framework second, deliberately
  • One framework taught as a vehicle, not as the curriculum
You build

Your Stage 5 system extended into an agent that retrieves, calls two real tools (a calendar, a ticketing API, a database), and refuses or falls back safely when it should.

7

The differentiatorEvaluation

Taught in full here, referenced from Stage 1

The skill that separates a demo from a product, and the one almost every course skips. Building a test set, using a model as a judge, human review, regression tests for prompts, measuring hallucination and retrieval quality, tracing, and the discipline of running the evaluation before every change instead of eyeballing outputs.

Evaluation is asked of almost half of senior AI engineers and almost no juniors. That gap is the point: a beginner who arrives with an evaluation suite is showing the evidence seniors are hired for.

You build

An evaluation suite for your Stage 6 agent, with a written report of what it gets wrong and one change that measurably improved it.

8

ProductionShipping it

What makes it production-grade

"Production" is the word employers use most. This stage earns it: containerise the agent with Docker, deploy it to one cloud, set up CI/CD that runs the tests and the evaluations before anything goes live, add logging and monitoring, put authentication on the API, handle personal data properly, and track cost per request.

  • One cloud, deployed properly, beats three clouds' certificates
  • Security taught as engineering, not as a compliance slide
You build

Your agent live at a public URL, with a pipeline that blocks deployment if the evaluations regress, and a dashboard showing usage and cost.

03Phase 3Launch: the credential and the first roleStages 9–10
9

CapstoneA business problem, solved end to end

Presented as a business case, not a notebook

You choose a real organisational problem, scope it, build a retrieval-augmented, tool-using application with an evaluation suite, deploy it, and present it to a non-technical audience in terms of what it saves or enables. This is the credential.

You build

A public repository, a live deployment, an evaluation report, and a ten-minute recorded presentation to a business audience. This is your portfolio.

10

Getting hiredThe realistic first role

Honest about titles, salaries and search

The junior market is small, often degree-gated, and full of paid courses dressed up as job adverts. This stage is candid about that and gives you the counter-moves.

  • Which titles to search: Junior AI Developer, AI Automation Engineer, graduate technology and AI roles, developer or automation roles with an AI component
  • How to spot a paid course disguised as a vacancy
  • A CV that uses employer vocabulary: production, agentic workflows, RAG, evaluation, guardrails, measurable value
  • The Microsoft-stack route into regional and public-sector employers
  • Talking about AI-assisted development as a strength in interview
  • Progression: what turns a first role into a mid-level one in two to three years
You build

A CV in employer vocabulary, interview practice on your capstone, and a realistic search plan for your first role.

Deliberately Left Out

What We Don't Teach, and Why

What other AI courses include, and the job data says a first-role programme should not. If you are looking for these, this is not the right programme, and we would rather tell you now.

Training models from scratch

None of the adverts we analysed were pure machine learning. You learn to understand models, not to build them.

Deep learning maths

Backpropagation and gradients aren't asked for. The intuition for what training does is in Stage 0; the maths is not.

PyTorch and TensorFlow

Under a tenth of adverts. You will know what they are; you will not spend weeks on them.

Computer vision, classical NLP, transformer internals

The syllabus of a 2019 machine learning course.

A vendor certificate as the credential

No advert asked for one. Your deployed capstone is the credential.

After the core: the advanced tier

  • Kubernetes & Terraform

  • Building MCP servers
